# מפתח נכסים

סוכן חיפוש נכסים בישראל. מקבל שאלה בשפה חופשית, מסנן ומדרג, ומחזיר כרטיס נכס אחד שבו
כל מה שדרוש להחלטה: המחיר מול חציון האזור, מס הרכישה לפי הפרופיל שלך, ההון העצמי
הנדרש, התשואה, העלות החודשית המלאה, מצב הרישום והדגלים האדומים.

מכסה קנייה יד שנייה, שכירות, יחידות דיור וסטודיו, והשקעה לפי תשואה.

## הרצה

```bash
npm install
npm run dev          # http://localhost:3000
npm test             # 237 בדיקות יחידה
npm run typecheck
npm run build
```

מסד הנתונים הוא libSQL. בלי הגדרות הוא קובץ מקומי ב-`data/app.db`, שנוצר ונזרע אוטומטית
בהתחברות הראשונה מ-`src/lib/seed-data.ts`. `npm run db:reset` מוחק אותו.

## פריסה

הקוד רץ כמו שהוא גם מקומית וגם serverless, כי שכבת הנתונים היא **libSQL** — אותו דרייבר
מדבר גם עם קובץ מקומי (`file:`) וגם עם מסד מנוהל (`libsql://`). זה מכוון: פריסה serverless
היא בלי דיסק שאפשר לכתוב אליו, ודרייבר מקומי נפרד היה אומר שמסלול הקוד שנפרס אינו זה
שנבדק.

### Vercel + Turso

```bash
# 1. מסד מנוהל
turso db create mafteach-nechasim
turso db show mafteach-nechasim --url          # libsql://...
turso db tokens create mafteach-nechasim       # הטוקן

# 2. פריסה
vercel link
vercel env add DATABASE_URL production         # הדביקו את ה-URL
vercel env add DATABASE_AUTH_TOKEN production  # הדביקו את הטוקן
vercel deploy --prod
```

הסכמה והזריעה מורצות אוטומטית בבקשה הראשונה, אז אין צורך במיגרציה ידנית.

**הגנה מכוונת:** אם האפליקציה רצה על Vercel או Lambda **בלי** `DATABASE_URL`, היא נופלת
מיד עם הודעה מפורשת. היא לא נופלת חזרה לקובץ מקומי — כי הפלטפורמה תמחק אותו בין הפעלות,
וזה ייראה כמו נתונים שנעלמים בשקט.

`.env.example` מתעד את כל משתני הסביבה.

## API

| נתיב | תיאור |
|---|---|
| `GET /api/search?q=...&profile=...&sort=...` | חיפוש. `q` הוא טקסט חופשי בעברית; פרמטרים מפורשים גוברים על מה שנפרס ממנו |
| `GET /api/properties` | כל הנכסים |
| `POST /api/properties` | הוספת נכס (JSON). מחזיר 422 עם שגיאות פר־שדה |
| `POST /api/import` | ייבוא CSV. שורות תקינות נקלטות, פסולות מדווחות לפי מספר שורה |
| `POST /api/enrich` | שליפת נתוני שוק ממקור וכתיבתם עם פרוביננס. גוף: `{id}` / `{ids}` / ריק לכל המאגר, עם `force` לעקיפת המטמון |
| `GET /api/resolve?address=...` | כתובת → גוש/חלקה, עם רמת ודאות ועם פירוק הכתובת כפי שהובנה |
| `GET\|POST\|DELETE /api/searches` | חיפושים שמורים |
| `POST /api/searches/run` | הרצת חיפושים שמורים והחזרת מה שהשתנה. `{"dryRun":true}` בודק בלי לסמן כנקרא |
| `GET /api/report/:id?profile=...` | דוח הנכס כ-PDF. הפרופיל בשאילתה כי המס והמימון אישיים |
| `POST /api/extract` | `{text}` / `{url}`, או `multipart` עם `image` → טיוטת נכס עם רמת ודאות לכל שדה |

```bash
curl -s --get http://localhost:3000/api/search \
  --data-urlencode 'q=4 חדרים בחיפה עד 2 מיליון עם מעלית וחניה' \
  --data-urlencode 'profile=single'
```

## הדבקת מודעה

זהו ערוץ המלאי שאינו תלוי באף צד שלישי. מדביקים טקסט מודעה מכל מקור — יד2, פוסט
בפייסבוק, הודעת ווטסאפ, תיאור סרטון — והשדות מתמלאים. כל שדה מוצג עם **המילים שממנו
נגזר** ועם רמת ודאות: ירוק לנאמר במפורש, כתום להוסק מההקשר. המשתמש מאשר או מתקן.

### שלוש דרכים להדביק

1. **טקסט** — העתקה של המודעה. הדרך המהימנה ביותר.
2. **דף שלם (Cmd+A)** — מותר ואף נוח. המערכת מאתרת בתוך הדף את אזור המודעה לפי צפיפות
   סימנים (חדרים, מ״ר, קומה, גוש, מחיר) ומשמיטה את השאר, ומדווחת כמה תווים הושמטו.
3. **צילום מסך** — הדבקת תמונה ישירות לתיבה (Cmd+V) או העלאת קובץ. נקרא ב-OCR עברי על
   השרת. קריאה בביטחון נמוך מ-55% מדווחת ככזו ולא מוזנת לחילוץ.

#### שני באגים ש-Cmd+A חשף

דף מודעות מכיל **מודעות אחרות**, ובהן המספרים הגדולים בדף:

- **המחיר** נלקח כסכום הגדול ביותר — כלומר של פנטהאוז אחר ב-12.5 מיליון. הפתרון: צמצום
  לאזור המודעה, ועצירה בכותרות כמו „מודעות נוספות שיעניינו אותך”, ששורותיהן נושאות כל
  סימן אפשרי.
- **השטח** נלקח כגדול ביותר, ולכן 200 מ״ר של אותו פנטהאוז. עכשיו נלקח **הראשון** שמוזכר:
  מודעה מציינת את שטחה שלה בתחילתה.

### למה טקסט ולא קישור

| מקור | מה עובד | למה |
|---|---|---|
| יד2, מדלן, לוחות מסחריים | טקסט בלבד | שליפה אוטומטית של דפיהם מפרה ToS, גם כשהמשתמש הדביק את הקישור |
| פייסבוק, אינסטגרם, טיקטוק | טקסט בלבד | חוסמים בוטים ודורשים התחברות — בקשת שרת מקבלת דף login |
| ווטסאפ, טלגרם | טקסט בלבד | לא נגיש לשרת |
| יוטיוב | טקסט, או קישור עם מפתח | דרך YouTube Data API הרשמי |
| אתר כללי | קישור או טקסט | בכפוף ל-robots.txt |

`classifyUrl` מסווג את הקישור **לפני** ניסיון השליפה, כך שהמשתמש מקבל הנחיה מיידית
במקום להמתין לכישלון.

### מה המחלץ יודע

עסקה, סוג נכס, חדרים (כולל חצאים), שטח בנוי ומרפסת בנפרד, קומה ומתוך כמה, שנת בנייה,
מצב, עיר ורחוב, גוש וחלקה, מחיר, ארנונה, ועד בית, תאריך כניסה, ומאפיינים.

שלוש נקודות שהן כל ההבדל בין מחלץ שעובד לאחד שמזיק:

- **שלילה.** „ללא מעלית”, „בלי חניה”, „אין ממ״ד” חייבים להתפרש כ-false. מחלץ שקורא
  „מעלית” ומסיק „יש” הוא גרוע משדה ריק.
- **ארנונה וועד בית נקראים לפני המחיר**, אחרת סכום מתויג נבלע כמחיר הנכס.
- **הרחוב מחולץ בחלון תחום.** שם רחוב הוא מילה או שתיים עם מספר. בלי התיחום, פוסט באורך
  פסקה הופך כולו ל„שם הרחוב”.

## דוח נכס (PDF)

`GET /api/report/:id?profile=...` מפיק PDF בעברית: זיהוי הנכס, מאפיינים, מחיר ושוק,
מס רכישה מדרגה־מדרגה, עלות כניסה והון עצמי, תשואה, רישום ותכנון, עסקאות השוואה,
ובסוף **„מה נשאר לבדוק”** — הפרק שבאמת שווה משהו לעורך דין.

הצ׳קליסט נגזר ממה שהרשומה אומרת **ומה שהיא לא אומרת**, בשלוש דרגות: חוסם, נדרש, מומלץ.
רישום שלא אומת מעלה את „נסח טאבו” מ„נדרש” ל„חוסם”; יחידת דיור בלי היתר פיצול היא חוסם;
משפר דיור מקבל חוסם על חלון המכירה הסטטוטורי; משקיע מקבל תזכורת שהשיעורים הם הוראת שעה.
„לא בדקנו” מייצר פריט ולא שתיקה.

### הבאג שרק העין תפסה

`pdf-lib` עושה layout דרך `fontkit`, ו-fontkit מסדר עברית **כמעט** נכון: סדר המילים תקין,
אבל הוא לא מריץ את אלגוריתם ה-bidi המלא ולכן הופך גם מספר משובץ. „גוש 6128” יוצא
„גוש 8216” — חלקה שנראית סבירה ואינה זו שברשומה. הוא גם לא מחליף תווי מראה, אז סוגריים
יוצאים הפוכים.

להריץ bidi בעצמנו ולהעביר ל-fontkit טקסט מסודר מראש **מחמיר** את זה, כי fontkit מסדר שוב.
לכן `src/lib/bidi.ts` עושה תיקון צר: הופך מראש כל ריצת LTR כדי שההיפוך של fontkit יחזיר
אותה, ומחליף סוגריים מחוץ לריצות האלה. הוא גם **לא נוגע** בטקסט בלי עברית — אחרת תווית
מדרגת מס „0–1,978,745” הופכת ל„0–547,879,1”.

**אף מחלץ טקסט לא יכול לאמת את זה.** `pdftotext` מחיל bidi משלו ומדווח מספר שאינו זה
שמצויר; `pdftotext -bbox` ו-`pdftoppm` סתרו זה את זה. הדרך היחידה שעבדה: לרנדר לתמונה
ולהסתכל על הדף.

## חיפושים שמורים והתראות

חיפוש שמור הוא מנדט: מה מחפשים, לפי איזה פרופיל קונה, ומאיזה ציון ומעלה שווה להפריע.
`POST /api/searches/run` משווה את ההרצה הנוכחית לקודמת ומדווח **רק על מה שהשתנה**.

שלושה סוגי שינוי: ירידת מחיר, נכס חדש שעונה על התנאים, והתאמה שעלתה ב-5 נקודות ומעלה.
ההתראה נושאת את הסיבה ולא רק את העובדה — `ירד ב־₪160,000 (9.0%) — כעת 20.9% מתחת לחציון
האזור · תשואה 4.4% · 72 ימים בשוק`, לא „נכס חדש”.

### ארבע החלטות שנאכפות בקוד

- **ההרצה הראשונה רושמת מצב פתיחה בלבד.** להכריז על כל התאמה קיימת כ„חדשה” ברגע ששומרים
  חיפוש זה רעש, והוא מאמן את המשתמש להתעלם מההתראה הבאה — זו שבאמת קרתה. ב-DB `seen = NULL`
  מבדיל בין „מעולם לא רץ” לבין „רץ ולא מצא כלום” (`'{}'`).
- **תצוגה מקדימה לא צורכת התראות.** טעינת המסך רצה עם `dryRun`, אחרת רענון דף היה מוחק
  בשקט את מה שהוא בדיוק עמד להציג.
- **סף הציון חותך לפני הדיף**, כך שנכס מתחת לסף לא נכנס גם ל-baseline ולא „יתפוצץ” כשהסף
  יורד.
- **ירידת מחיר קודמת לנכס חדש** בסדר ההצגה: היא האירוע הנדיר והפעיל יותר.

**אין מתזמן ברקע.** `POST /api/searches/run` הוא הנקודה שאותה cron חיצוני אמור לקרוא.

## השוואה

בכרטיס יש „הוספה להשוואה”, ועד ארבעה נכסים נפרשים בטבלה אחת: מחיר ומחיר למ״ר, שטח
ומאפיינים, עלות חודשית, עלות כניסה מלאה, תשואה, רישום ותכנון, סביבה, ודגלים.

הערך העדיף בשורה מודגש — **אבל רק כשההדגשה אומרת משהו.** `pickBest` מחזיר `null`
בשלושה מקרים:

- לשורה אין כיוון („ימים בשוק” זה גם מרחב למשא ומתן וגם סימן שאלה; „כיווני אוויר” הוא
  עניין של טעם).
- כל הערכים זהים. הדגשת „מנצח” בין ערכים שווים ממציאה הבחנה שהנתונים לא תומכים בה.
- יש תיקו על הערך המנצח. שני נכסים עם מס רכישה ₪0 — אף אחד לא „זול יותר”.

מכירה ושכירות לא מושוות זו לזו: היחידות שונות, ולכן בבחירה מעורבת השורות הכספיות
מאבדות את ההכרעה ומוצגת אזהרה.

## מקורות נתוני שוק

חציון האזור ועסקאות ההשוואה מגיעים משכבת מקורות מוחלפת (`src/lib/sources/`). כל נתון
נשמר עם `marketSourceId`, `marketStatus`, `marketSampleSize` ו-`marketFetchedAt`,
והכרטיס מציג אותם.

| `MARKET_SOURCE` | מקור | מצב |
|---|---|---|
| ברירת מחדל | `FixtureSource` — עסקאות מתוך מאגר הדוגמה | עובד |
| `nadlan` | `NadlanSource` — נדל״ן של רשות המסים | **לא אומת מול השירות החי** |

אדפטר נדל״ן נכתב מול מבנה הבקשה המתועד, אך **מעולם לא הרצנו אותו מול השירות האמיתי** —
מדיניות הרשת של סביבת הפיתוח חוסמת את `gov.il` ומחזירה 403. יש להריץ אותו מול הנקודה
האמיתית ולתקן את שמות השדות ב-`parseDeals` לפני הסתמכות. הוא לעולם לא זורק חריגה ולעולם
לא ממציא מספר: כל כשל הופך ל-`unavailable`, והמערכת משאירה את הנתונים הקיימים כפי שהם.

## איתור גוש וחלקה מכתובת

`GET /api/resolve` ממיר כתובת חופשית לגוש/חלקה. הטופס ב-`/add` משתמש בזה, כך שאין חובה
לדעת גוש וחלקה כדי להזין נכס.

| `PARCEL_SOURCE` | מקור | מצב |
|---|---|---|
| ברירת מחדל `gazetteer` | בניינים שכבר במאגר | עובד |
| `gazetteer,govmap` | נופל ל-GovMap כשהמאגר לא יודע | **GovMap לא אומת מול השירות החי** |

הגזטיר עובד בלי רשת על סמך עובדה פשוטה: כל הדירות בבניין חולקות גוש וחלקה. ברגע שיחידה
אחת בכתובת מאונדקסת, הבאות נפתרות מיד. הוא מחזיר **שלוש רמות ודאות**, וזו ההבחנה שמונעת
את הנזק:

- `exact` — התאמת בניין מדויקת. הטופס ממלא גוש **וחלקה**.
- `street` — אותו רחוב, מספר בית אחר. הטופס ממלא עיר ורחוב, **ומשאיר את החלקה ריקה**.
  חלקה של בניין שכן שהוזנה כחלקה של הנכס הזה גרועה משדה ריק: כל שליפה רשמית בהמשך תהיה
  של נכס אחר.
- `none` — הזנה ידנית, עם הסבר מה חסר בכתובת.

נרמול הכתובות (`src/lib/address.ts`) מטפל בתחיליות (`רח׳`, `שדרות`, `דרך`), בקיצורי ערים
(`ת״א`, `ב״ש`, `ראשל״צ`), בגרשיים ומרכאות בכל הווריאציות, במספר בית עם אות (`14א`),
ובפרטי יחידה (`דירה 3`, `קומה 2`) שמושמטים ומדווחים. אותו בניין שנכתב בחמש צורות שונות
מתמפה למפתח אחד.

**מגבלה:** זיהוי העיר מוגבל לערים שכבר במאגר ולרשימת הקיצורים. עיר שאינה מוכרת נבלעת
לתוך שם הרחוב, והתוצאה היא `none` — זה מה ש-GovMap אמור לכסות בסביבה עם רשת.

### שלושה כללים שנאכפים בקוד

1. **מדגם דק לא מצוטט כאחוז.** מתחת ל-3 עסקאות הסטטוס הוא `thin`, ו-`deltaVsArea`
   מוחזר `null`. הכרטיס מציג „מדגם קטן — N עסקאות” במקום „12% מתחת לחציון”.
2. **מקור שנכשל לא דורס נתונים.** נכס שהמקור לא ידע עליו נשאר עם מה שהיה לו ומדווח
   ב-`skipped` עם סיבה.
3. **המטמון ממופתח לפי מקור.** החלפת `MARKET_SOURCE` לא תגיש מספרים של מקור אחד תחת
   שמו של אחר. תוצאה זמינה נשמרת ליום; כשל נשמר לחמש דקות בלבד.

## החלטות תכן

**גוש/חלקה הוא המפתח הראשי**, לא הכתובת — כתובות בישראל נכתבות בשש צורות, וגוש/חלקה
מזהה חד־ערכית מול נדל״ן, טאבו ו-GovMap. מזהה הישות נגזר ממנו, כך ששתי מודעות לאותו
נכס משני מקורות מתנגשות ביודעין.

**שדות מחושבים אינם נשמרים.** מס רכישה, תשואה, הון עצמי ופער מול האזור תלויים בפרופיל
המשתמש ובמדרגות שמשתנות בחקיקה. שמירה שלהם היא באג מובנה, ולכן הם נגזרים בזמן ריצה
ולא מתקבלים כקלט.

**„לא בדקנו” שונה מ„בדקנו ואין”.** `registryVerified: false` ו-`splitPermit: 'unknown'`
הם ערכים תקפים שמייצרים דגל, ולא שדות ריקים.

**דגל אדום לא מסתיר נכס.** הוא מוריד 25 נקודות מהציון ומסביר למה — ההחלטה נשארת של
המשתמש.

## מדרגות המס

הסכומים הם מהדורת 16.1.2025, שהוקפאה בחוק ההסדרים 2025 ומפורסמת מחדש ללא שינוי
בחוזר מס רכישה 1/2026 של רשות המסים לתקופה 16.1.2025–15.1.2028.

נקודות שנבדקות ב-`tests/tax.test.ts` כי הן הטעויות הנפוצות בשוק:

- **משפר דיור** ממוסה במדרגות דירה יחידה, לא 8% משקל ראשון, בתנאי מכירה בחלון הסטטוטורי.
- **עולה חדש** מעל 20,183,565 ₪ — הקלת תקנה 12א אינה חלה כלל, והחישוב חוזר למדרגות
  הרגילות על מלוא השווי.
- **תקנה 11** — 2,500,000 ₪ הוא מצוק ולא מדרגה: שקל אחד מעל, ו-0.5% חלים על מלוא השווי.
- **דירה נוספת** — שיעורי 8%/10% הם הוראת שעה בתוקף עד **31.12.2026**. יש לאמת הארכה
  לפני הסתמכות עליהם ב-2027. הקבוע `ADDITIONAL_HOME_ORDER_EXPIRES` מסמן זאת בקוד ובממשק.

## מגבלות ידועות

- הנכסים במאגר הם **נתוני דוגמה** ואינם מלאי אמיתי.
- אדפטר נדל״ן לא אומת מול השירות החי (ראו „מקורות נתוני שוק”). ברירת המחדל היא fixtures.
- אדפטר GovMap לא אומת מול השירות החי; ברירת המחדל היא הגזטיר המקומי.
- אין שליפת מידע תכנוני (תוכניות, תמ״א) או רישומי (נסח טאבו) — שניהם עדיין ידניים.
- שכר הדירה האזורי (`areaMedianRent`) עדיין מוזן ידנית ואינו מועשר.
- תקרת הפטור ממס על הכנסה משכירות אינה מגולמת בחישוב התשואה נטו.
- `next` גורר גרסת `postcss` עם התראת audit; אין תיקון בלי שדרוג שובר.
- OCR רץ על השרת ולוקח כשנייה לתמונה. בפריסה serverless ייתכן שיידרש timeout ארוך יותר,
  ונתוני השפה (5.2MB) נכללים ב-bundle דרך `outputFileTracingIncludes`.
- ה-PDF נבדק חזותית על מבחר מחרוזות ועל דוח מלא, לא על כל מחרוזת אפשרית. מחרוזת עם
  תבנית מספרית חדשה עלולה לדרוש הרחבה של `LTR_RUN` ב-`src/lib/bidi.ts` — ואימות בתמונה.
